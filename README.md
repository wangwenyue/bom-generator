# 元件清单助手

一个运行在 GitHub Pages 上的纯前端工具，用于读取元件 Excel 清单、合并重复物料、查询物料数据库，并按标准模板生成可下载的 Excel 文件。

## 主要功能

- 自动识别“12位编码”和“位号”列，数量由位号公式自动计算
- 按 12 位编码合并重复物料及位号
- 通过本地物料库补全名称、规格型号和封装
- 对格式错误或未查到的编码醒目标记
- 自动递增版本号的最后一位
- 保留加工工艺说明页，生成倒序更新记录
- 物料库支持 Excel/CSV 导入并保存在当前浏览器的 IndexedDB
- 仓库不包含真实物料数据，导入内容不会上传到 GitHub 或服务器

## 本地运行

直接使用任意静态文件服务器打开项目根目录，例如：

```bash
python3 -m http.server 8000
```

然后打开 `http://127.0.0.1:8000/`。

## 物料库格式

导入的 Excel 或 CSV 需包含以下表头：

| 12位编码 | 物料名称 | 规格型号 | 封装 |
|---|---|---|---|
| 000000000001 | 示例物料 | 示例型号 | 示例封装 |

首次使用时导入公司物料总表；后续访问会自动读取当前浏览器保存的数据。“追加更新”会把新物料合并进现有库，不会删除原有物料。相同 12 位编码的物料若在名称、规格型号或封装上存在实质差异，页面会逐条展示新旧数据并由用户选择采用哪一条；空格、全半角、大小写及常见标点差异不会被判定为冲突，数量和位号不参与判断。如需建立一份完全独立的新库，请先点击“清除本地库”，再导入新总表。

“导出总表”可随时把当前浏览器中的完整物料库导出为 Excel，适合备份、迁移或核查。换浏览器、换电脑或清除网站数据后，需要重新导入此前导出的总表。

## 隐私说明

物料总表和用户上传的清单仅在当前浏览器本地处理并保存在 IndexedDB，不会上传到 GitHub 或其他服务器。仓库内的 `materials.json` 为空，公开的 Excel 模板和测试文件仅包含虚构占位数据。

## 部署

仓库包含 GitHub Pages Actions 工作流。在 GitHub 仓库设置中将 Pages 的 Source 选为 **GitHub Actions** 后，推送 `main` 分支即会自动部署。
