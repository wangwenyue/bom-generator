# 元件清单助手

一个运行在 GitHub Pages 上的纯前端工具，用于读取 Candace 导出的 `.BOM` 文件或元件 Excel 清单、查询本地物料数据库，并按标准模板生成可下载的 Excel 文件。

## 主要功能

- 直接读取 Candace 导出的 `.BOM` 文件，按 `GGXH`（规格型号）查询本地物料库
- 继续兼容包含“12位编码”和“位号”列的 `.xlsx` / `.xlsm` 清单
- 支持规格型号完全匹配和“库内规格型号完整包含 GGXH”的包含匹配
- 按 12 位编码合并重复物料及位号
- 数量根据位号数量自动计算，无需用户输入
- 对未匹配物料、编码错误、重复位号和主备选关系进行预览校验
- 未匹配物料可整行粘贴“12位编码、物料名称、规格型号、封装”，确认后自动追加到本地物料库
- 识别带 `/NC` 或 `NC/` 的物料，并要求用户确认空贴或正常贴装；空贴物料不会进入最终清单
- 提示同封装、同阻值但精度不同的电阻，支持合并到高精度物料或分别保留
- Excel 来源自动递增版本号末位；BOM 来源默认沿用文件名中的版本号和日期
- 保留加工工艺说明页，生成倒序更新记录
- 输出按电容、电阻、电感、三极管、二极管、芯片等类别排列，插座和连接器置于最后
- 物料库支持 Excel/CSV 导入并保存在当前浏览器的 IndexedDB
- 仓库不包含真实物料数据，导入内容不会上传到 GitHub 或服务器

## 输入文件

### Candace BOM

支持扩展名为 `.BOM` 的制表符分隔文本，文件中需包含以下表头：

| Item | Quantity | Reference | Part | GGXH |
|---|---|---|---|---|

其中 `Reference` 用于生成位号和数量，`GGXH` 用于查询本地物料库。文件名中的版本和日期会被识别，例如：

```text
ZNSP_3.0_ZJ_ZKB_V1_0_1_20230223.BOM
```

对应版本 `V1.0.1`、日期 `2023-02-23`。

### Excel 清单

支持 `.xlsx` 和 `.xlsm`，至少需要包含“12位编码”和“位号”两列；“物资分类”列可选。Excel 来源会沿用模板信息，并将版本号最后一位自动加一。

## 本地运行

直接使用任意静态文件服务器打开项目根目录，例如：

```bash
python3 -m http.server 8000
```

然后打开 `http://127.0.0.1:8000/`。

## 物料库格式

导入的 Excel 或 CSV 需包含以下表头：

| 12位编码 | 物料名称 | 规格型号 | 封装 |
|---|---|---|---|
| 000000000001 | 示例物料 | 示例型号 | 示例封装 |

首次使用时导入公司物料总表；后续访问会自动读取当前浏览器保存的数据。“导入总表”会把新物料合并进现有库，不会删除原有物料。相同 12 位编码的物料若在名称、规格型号或封装上存在实质差异，页面会逐条展示新旧数据并由用户选择采用哪一条；空格、全半角、大小写及常见标点差异不会被判定为冲突，数量和位号不参与判断。如需建立一份完全独立的新库，请先点击“清除本地库”，再导入新总表。

“导出总表”可随时把当前浏览器中的完整物料库导出为 Excel，适合备份、迁移或核查。换浏览器、换电脑或清除网站数据后，需要重新导入此前导出的总表。

## 隐私说明

物料总表和用户上传的清单仅在当前浏览器本地处理并保存在 IndexedDB，不会上传到 GitHub 或其他服务器。仓库内的 `materials.json` 为空，公开的 Excel 模板和测试文件仅包含虚构占位数据。

## 部署

仓库包含 GitHub Pages Actions 工作流。在 GitHub 仓库设置中将 Pages 的 Source 选为 **GitHub Actions** 后，推送 `main` 分支即会自动部署。
